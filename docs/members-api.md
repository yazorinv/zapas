# Участники и порции

Контракт: Zapas API 0.0.3 и уточнения владельца проекта.

## Семантика профиля

- `GET member/{member_id}`: отображаемый профиль, локальные значения с подстановкой глобальных (`local ?: global`). Используется существующая модель `rooms.domain.model.Member`.
- `GET member/{member_id}/origin`: локальные значения внутри комнаты. `display_name` и `bio` могут быть `null`; модель `LocalMemberProfile` сохраняет их без подстановки.
- `POST member/{member_id}/profile`: изменение локального профиля, ответ соответствует `origin`.
- Для определения своего участника нужно сравнить `Member.userId` с `User.id` из существующего `user/me`. Неопределённый `userId` не означает владение.
- Удаление участников запрещено и в новом API-сервисе не представлено.

## Покрытие слоя данных

| Метод | Поддержка клиента |
| --- | --- |
| GET `member/{member_id}` | `GetMemberUseCase` |
| GET `member/{member_id}/origin` | `GetLocalMemberProfileUseCase` |
| POST `member/{member_id}/profile` | `UpdateMemberProfileUseCase` |
| GET `member/{member_id}/default_portions` | `GetDefaultPortionsUseCase` |
| POST `member/{member_id}/default_portions` | `SetDefaultPortionsUseCase` |
| POST `member/{member_id}/portion` | `SetMemberPortionUseCase` |
| GET `member/{member_id}/portions` | `GetMemberPortionsUseCase`, query-параметры `begin` и `end` по согласованному изменению сервера. |

## Правила порций

- Количество — `Long` (API `int64`), ноль разрешён. Use case отклоняет отрицательные значения.
- Дата передаётся в формате `yyyy-MM-dd`; проверяется существование календарной даты. Ограничения на прошлые и будущие даты пока не вводятся.
- Каждая запись создаётся сервером автоматически из значения по умолчанию. Клиент не создаёт записи при чтении, не заполняет пропуски и не пересчитывает историю при изменении значения по умолчанию.
- Изменять чужие порции нельзя. Будущий интерфейс должен скрывать действия для чужого участника; сервер обязан проверять права независимо от клиента. Слой API сам по себе не является проверкой прав.
- `begin` и `end` передаются без сдвигов. Включительность границ пока не уточнена; клиент не фильтрует ответ по собственной трактовке.
- Исходный YAML описывает JSON-тело для GET списка порций. Владелец проекта согласовал с сервером переход на query-параметры `begin` и `end`. Чтение периода требует выкладки этого изменения на сервере.

## Интеграция

`MembersApiService` использует общий Retrofit с авторизацией и обновлением токена. Репозиторий подключён в `AppModule`, сервис — в `NetworkModule`, use case доступны через constructor injection Hilt.

Экраны и навигация на этом этапе не изменяются.
